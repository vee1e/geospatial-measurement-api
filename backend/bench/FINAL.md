## Where the time goes

Profiled `process_file` on the 10,000-feature file took 0.609 s. The three biggest cost centres:

1. **Reading the KML**, `app/geo/readers.py` - 0.341 s cumulative (56% of the run): `ElementTree.parse` (0.088 s), coordinate parsing (`_parse_coordinates` 0.076 s) and property extraction (`_properties_from_placemark` 0.088 s). The layer extent is folded in here while the coordinates are parsed.
2. **Reprojecting and measuring**, 0.228 s: `Projector.prepare` pushes every coordinate of the layer through pyproj in one call (0.122 s), then `measure` walks the arrays with the shoelace formula (0.106 s). No geometry library runs per feature.
3. **Assembling and storing the document**, `app/pipeline.py` (`_build_payload`) minus the two above: about 0.014 s for the summary totals and the per-feature list that becomes the 3,029,802-byte JSON document, plus 0.027 s for the status updates and `db.save_measurements`.

Read once against the scaling table: no part of the pipeline grows faster than the feature count. Per-feature cost falls from 0.091 ms at 100 features to 0.028 ms at 10,000 because the fixed per-file cost (CRS resolution, import-time work already paid, one document write) is spread over more features. Memory grows linearly: 49.4 MB of growth for 10,000 features, about 4.9 KB per feature, over a 41.7 MB interpreter baseline.

Concurrency helps: the dispatcher hands each file to the process pool, so 8 simultaneous uploads take 0.16 s wall against 0.49 s serially.

Not measured here: RSS of the serving uvicorn process itself while requests run [not measured], disk write cost of the upload separated from network [not measured], and any allocation inside C extensions (pyproj, libexpat) which tracemalloc cannot see [not measured].
